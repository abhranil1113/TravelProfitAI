## 2. Item-by-Item Detailed Verification Analysis

### 1. F-01 — Classification Threshold Selection & OOF Predictions
* **Trace of OOF Prediction Generation:**
  In `modeling/cross_validator.py` (lines 122–158):
  - For each fold generated by `splitter.split(X, groups=groups)`:
    - Preprocessor and estimator are freshly instantiated and fitted **strictly** on `X_train = X.iloc[train_idx]` and `y_train = y.iloc[train_idx]`.
    - Predictions are generated on `X_val = X.iloc[val_idx]` via `artifact.predict_proba(X_val)`.
    - The validation predictions are placed into `oof_preds[val_idx] = val_prob`.
  - Because `train_idx` and `val_idx` are strictly disjoint, **no observation is ever evaluated by a model trained on that observation**.
* **Threshold Optimization Gating:**
  In `modeling/pipeline.py` (lines 224–274):
  - `optimize_classification_threshold()` is invoked **strictly** using `y_train_arr[valid_oof_mask]` and `oof_probs[valid_oof_mask]`.
  - The holdout test set (`X_test`, `y_test`) is never passed or referenced during threshold optimization.
  - The optimal threshold $T^*$ is selected via expected business cost minimization ($C_{\text{FN}}=3.0, C_{\text{FP}}=1.0$).
* **Frozen Application on Test Set:**
  In `modeling/evaluator.py` (lines 28–41):
  - `evaluate_test_set()` receives `frozen_threshold: Optional[float]`.
  - Predictions are generated via `preds = (pos_probs >= applied_threshold).astype(int)`.
  - There is zero threshold search or optimization code inside `evaluator.py`.

### 2. F-02 & F-03 — Demand Temporal Validation & Group Handling
* **Independent Target Generation:**
  In `modeling/target_builder.py` (lines 52–90):
  - `groups = daily.groupby(["destination_id", "inventory_type"])` groups records by entity pair.
  - For each entity, a continuous daily date range is generated (`full_idx = pd.date_range(..., freq="D")`), zero-filling missing search days.
  - Lags (`lag_1`, `lag_7`, `lag_14`) and rolling statistics are computed strictly within that entity's series.
  - Target `future_search_volume_7d` is generated via `vol.shift(-7)` strictly within that entity's series.
  - No cross-entity target contamination or search volume leakage can occur.
* **Global Chronological Ordering:**
  Line 98: `panel_clean = panel_clean.sort_values(["date", "destination_id", "inventory_type"]).reset_index(drop=True)`.
  - All 10 destination/inventory entities appear together on each calendar date.
  - Global chronological slicing guarantees that early, middle, and late temporal windows contain all eligible entities.
* **Exact Calendar Embargo Arithmetic:**
  In `modeling/splitters.py` (`PurgedGroupTimeSeriesSplit.split()`, lines 70–82):
  - `dates = pd.to_datetime(group_s)`
  - `unique_dates = pd.Series(sorted(dates.unique()))`
  - `embargo_cutoff_date = last_train_date + pd.Timedelta(days=self.embargo_gap)`
  - `remaining_val_dates = unique_dates[unique_dates > embargo_cutoff_date]`
  - Embargo is calculated with `pd.Timedelta(days=7)`, not integer row counts.
* **Zero Target Horizon Overlap:**
  - In training, the latest observation date is `last_train_date`. Its target horizon is $\text{last\_train\_date} + 7\text{ days}$.
  - Validation observation dates are strictly $> \text{last\_train\_date} + 7\text{ days}$ (i.e. $\ge \text{last\_train\_date} + 8\text{ days}$).
  - Training target outcomes are completely realized before the earliest validation observation begins.
* **Edge Cases (Missing Dates, Duplicates, Multi-Entity):**
  - Handled cleanly: `unique_dates` deduplicates identical dates across entities; boolean indexing (`dates.isin(train_dates)`) selects all entities present on those dates; calendar date addition (`+ pd.Timedelta`) enforces physical 7-day separation even if calendar gaps exist.

### 3. F-04 — Hyperparameter Tuning Embargo Gap
* **Splitter Configuration:**
  In `modeling/hyperparameter_tuning.py` (lines 71–83):
  - `gap = task_config.business_params.get("embargo_gap_days", 0) if is_time_based else 0`
  - Passes `gap=gap` into `get_cross_validation_splitter()`, returning `PurgedGroupTimeSeriesSplit(n_splits=3, embargo_gap=7)`.
* **Group Propagation into RandomizedSearchCV:**
  - `search.fit(X_train, y_train, groups=groups)` (line 100).
  - In `modeling/pipeline.py` (lines 176–184), `groups_train = dates_full.iloc[train_indices]` is passed into `tune_model_hyperparameters()`.
  - Date information reaches the custom splitter during hyperparameter search.
* **Zero Test Exposure:**
  - `tune_model_hyperparameters()` is called with `X_train` and `y_train` only. The test set (`X_test`, `y_test`) is never referenced.

### 4. F-05 — Rapid Profiling Temporal Sampling
* **Test Cutoff Stability:**
  In `modeling/pipeline.py` (lines 68–101):
  - Partitioning into `X_train_full`, `y_train_full`, `X_test`, `y_test` occurs on the **full dataset** first.
  - Slicing uses unique date quantiles (85% cutoff) and a 7-day calendar embargo.
  - `X_test` and `y_test` are fixed and frozen before sampling logic is reached.
* **Sampling Application:**
  In `modeling/pipeline.py` (lines 127–146):
  - If `sample_size` is provided: `X_train = X_train_full.iloc[-sample_size:].copy().reset_index(drop=True)`.
  - `X_test` remains identical between sampled runs and full-dataset runs.
  - Slicing `iloc[-sample_size:]` takes the contiguous recent tail of the training set, preserving chronological ordering and boundary alignment with the embargo and test set.

### 6. F-07 — Multi-File Atomic Persistence
* **Staging Directory Lifecycle:**
  In `modeling/model_persistence.py` (`save_model_artifact()`, lines 130–231):
  1. `staging_dir = target_parent / f".staging_{task_config.task_name}_{timestamp_str}"`
  2. All three files (`estimator.joblib`, `preprocessor.joblib`, `metadata.json`) are dumped into `staging_dir`.
  3. If dumping fails, the `finally` block removes `staging_dir` via `shutil.rmtree(staging_dir, ignore_errors=True)`. `target_dir` is never touched.
* **Promotion & Rollback:**
  - If `target_dir` exists: it is renamed to `backup_dir = target_parent / f".backup_{task}_{timestamp}"`.
  - `staging_dir.rename(target_dir)` promotes the staged directory.
  - If promotion succeeds: `shutil.rmtree(backup_dir)` removes the backup.
  - If promotion fails: `backup_dir.rename(target_dir)` automatically restores the previous champion.
* **Model Version Integrity:**
  - Estimator, preprocessor, and metadata are written together in the same staging container before promotion, preventing mismatched estimator/preprocessor pairs.

### 7. F-08 — Dataset Fingerprinting Semantics
* **Separation of Concerns:**
  In `modeling/model_persistence.py`:
  - `compute_schema_fingerprint()` (lines 33–49): SHA-256 over dataset name, row count, and sorted column names (`fingerprint_type="schema_digest"`).
  - `compute_dataset_content_fingerprint()` (lines 52–71): SHA-256 over deterministic sample row values of the dataframe (`fingerprint_type="deterministic_content_digest"`).
  - Both fingerprints are recorded in `metadata.json` with explicit `algorithm="sha256"` and type labels, while maintaining backward compatibility for `meta["dataset_fingerprint"]["schema_digest_sha256"]`.

### 8. F-09 — Hotel Cancellation Booking Date Proxy
* **Code & Metadata Documentation:**

  - No claims of actual transaction-timestamp validation are made.

### 9. F-10 — Optimizer Service Integration Alignment
* **Service Decoupling Preserved:**
  - `backend/app/services/forecasting_service.py` and `optimization_service.py` remain untouched.
  - **ML Demand Semantics:** In Phase 4, the ML model predicts future destination search volume at $t+7\text{d}$ (`future_search_volume_7d`), representing search demand volume.
  - **Optimizer Demand Semantics:** In Phase 5, the optimization solver requires target inventory unit demand per category and supplier offer prices to solve procurement budget MILP.
  - **Phase 5 Contract:** Phase 5 will implement an adapter mapping search demand predictions into inventory unit demand curves using conversion rate multipliers and safety stock service levels.

### 10. Test Safety & DDL Audit
* **Database Operations in Test Suite:**

    - `Base.metadata.create_all(bind=test_engine)`
    - Custom SQLite index DDL: `DROP INDEX IF EXISTS`, `CREATE UNIQUE INDEX IF NOT EXISTS`
    - Test user seeding (`admin`, `pm`, `analyst`, `inactive`)
    - Teardown: `Base.metadata.drop_all(bind=test_engine)`
  - **Safety Rule Confirmation:**
    - If `pytest` is run from the workspace root without targeting, pytest discovers `backend/tests/conftest.py` and attempts SQLite DDL and seeding.
    - All unit tests in `tests/modeling/` (`test_splitters.py`, `test_model_persistence.py`, `test_evaluator.py`, `test_cross_validation.py`, etc.) are 100% pure in-memory unit tests that never import SQLAlchemy or `conftest.py`.
    - **Enforcement:** Test execution remains strictly prohibited as mandated by safety constraints.
